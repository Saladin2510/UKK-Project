Logika Perhitungan Pajak PB1 & Diskon Bertingkat (Slide 5 MUK)

🎯 Kunci Jawaban Wajib Dihafal ke Asesor:

"Pajak restoran PB1 10% dihitung dari DPP (Dasar Pengenaan Pajak), yaitu nilai belanja bersih setelah dikurangi diskon, bukan dari subtotal kotor. Hal ini sesuai dengan Undang-Undang Perpajakan Daerah dan skenario MUK Kasir."

Komponen Rumus Perhitungan Contoh Skenario MUK (Slide 5)
Subtotal Kotor Σ (harga × qty) Nasi Goreng (25k) + Ayam Bakar (28k) + Es Teh (5k) = Rp58.000
Diskon Bertingkat ≥200k (15%), ≥50k (10%), <50k (0%) Subtotal Rp58.000 masuk Tier 1 (10%) = -Rp5.800
Diskon Member Pelanggan terdaftar: ekstra +5% Jika non-member: 0%, Jika member: +5%
DPP (Dasar Pajak) Subtotal - Total Diskon Rp58.000 - Rp5.800 = Rp52.200
Pajak Restoran PB1 DPP × 10% Rp52.200 × 10% = Rp5.220
Total Akhir Bayar DPP + Pajak PB1 Rp52.200 + Rp5.220 = Rp57.420

Panduan Modifikasi Kode Langsung (*Live Coding*)

Skenario A: Asesor meminta mengubah batas atau persen diskon

Buka berkas src/helpers/kalkulator.js baris 45-54:

function hitungDiskonBertingkatPersen(subtotal) {
  const nominal = Number(subtotal) || 0;
  if (nominal >= 100000) return 20; // Ubah ambang atau persentase di sini
  if (nominal >= 50000) return 10;
  return 0;
}

Pertanyaan Kritis Asesor & Jawaban Ideal

1. Kenapa transaksi checkout menggunakan Database Transaction (ACID)?

Karena transaksi melibatkan multiple query (simpan header nota, simpan detail item, dan potong stok). Dengan beginTransaction(), commit(), dan rollback(), jika salah satu tahap gagal (misal stok kurang atau koneksi putus), sistem membatalkan seluruh perubahan ke kondisi awal. Hal ini menjamin integritas data (ACID).

2. Jelaskan relasi tabel transaksi dan produk!

Relasinya adalah Many-to-Many ($M:N$). Satu nota transaksi bisa membeli banyak produk, dan satu produk bisa dibeli di banyak transaksi. Untuk menghindari redundansi data dan memenuhi normalisasi 3NF, dibuat tabel pivot detail_transaksi yang menyimpan id_transaksi, id_produk, qty, dan harga_satuan riil saat transaksi terjadi.

3. Bagaimana sistem mencegah menu terhapus jika sudah pernah dibeli pelanggan?

Pada endpoint DELETE /api/menu/:id, backend mengecek apakah ID produk ada di tabel detail_transaksi. Jika ditemukan catatan transaksi, penghapusan ditolak dengan status HTTP 400 dan pesan edukatif menyarankan mengubah stok menjadi 0 agar audit finansial tidak rusak.

4. Mengapa antarmuka Kasir dan Admin dipisahkan secara eksklusif?

Menerapkan prinsip Role-Based Access Control (RBAC). Kasir berfokus pada kecepatan transaksi di kasir (katalog, pesanan, riwayat nota), sehingga laporan keuangan dan data akun pegawai disembunyikan. Sebaliknya, Administrator bertugas mengawasi performa bisnis toko, laporan pajak, dan manajemen karyawan tanpa perlu dibebani layar kasir meja depan.
